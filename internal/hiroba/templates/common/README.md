# __HIROBA_NAME__

This is an experimental Hiroba community application repository generated by `inari hiroba init`. It uses the one-repository-per-application layout, independently versioned OCI artifacts, immutable workflow callers, and the public Inari SDK contracts.

## Before onboarding

Reserve the permanent app ID in [`7K-Hiroba/community`](https://github.com/7K-Hiroba/community/blob/main/registry/apps.json), create the owning maintainer team, and complete [application onboarding](https://github.com/7K-Hiroba/community/blob/main/docs/governance/onboarding.md). The generated sources do not claim that a repository, team, release, or trusted source already exists.

After the package is published and its trusted source is configured, deploy it with its canonical source-qualified identity:

~~~sh
inari deploy <source>/__HIROBA_NAME__ --cluster <cluster-id> --file values.yaml
~~~

Short package names are local/display names only. Use the canonical `<source>/<package>` form when names collide.

## Development

Keep `package.yaml`/`template.yaml`, values schemas, canonical observability assets, generated chart/pack output, indexes, `releaseComponents`, and release metadata synchronized. Kind-qualified release identities prevent same-named components from colliding; artifact-bound smoke inherits its target identity. Run the repository's immutable PR callers and regeneration checks before submitting changes. Chartless observability still publishes the companion pack; chart-native output is optional. Fixture-only smoke suites are CI-only and are not application evidence.

The optional UI uses the stable `@7k-inari/ui-plugin-sdk@0.1.8` registry release and canonical `inari-ui-ext build`; no clone, postinstall, custom-webpack, or `@7k-hiroba` npm scope is used.
